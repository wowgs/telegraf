# Производительность

Сколько памяти у плагина, сколько стоят его операции и что в дизайне держит эту цену низкой. Главная дока — [Дизайн](design.md); плагин — [Плагин hostdash](plugin.md); страница — [Страница](ui.md).

## Условия замеров

Мак (Apple M5), `go1.27.1`, Node v26.10.0, 2026-10-27. Синтетика размером с 16-ядерный сервер: `interrupts` — 88 прерываний × 16 ядер (1408 серий), плюс 202 группы по 10 полей в 20 measurement, всего 3428 серий; полное окно — 360 точек на серию (1 ч при шаге 10 с). Значения `interrupts` — скорости с одним знаком после запятой (`12.3`), остальные — случайные `float64` полной точности. Go — медиана 20 прогонов или лучший из 5, как указано. На других машинах эти цифры не мерили.

## Память

| Где | Сколько |
| --- | --- |
| Плагин, 3428 серий, полное окно | 35,5 МиБ живой кучи после GC, около 30 Б на точку: 20 Б колонок (время, значение, номер записи), запас буферов, группы, карты |
| Страница, на точку серии | 16 Б: две колонки `Float64Array` (`Points` в `page/points.js`) |

Буфер серии при скользящем окне держится около окна: при 360 точках ёмкость не больше 512 на сервере (тест `TestBufferStaysNearTheWindow`) и не больше 1024 на странице при 100 000 записей (тест `pagetest/points.test.mjs`).

## Цена операций

| Что | Сколько |
| --- | --- |
| `Write` одного сбора, 1690 метрик | 0,49 мс вместе с созданием метрик в тесте (медиана 20) |
| `/api/layout`: построить и закодировать | 1,53 мс, 120 КБ (медиана 20) |
| Ответ ленты после одной записи, `interrupts` и один measurement из 10 серий | 0,50 мс, 30 КБ без сжатия (медиана 20) |
| `/api/series` за всё окно, `interrupts` (1408 серий), через обработчик плагина | без сжатия 2,37 МБ, 16,5 мс; gzip 829 КБ, 27,3 мс; zstd 862 КБ, 24,9 мс (лучший из 5) |
| То же, но значения `interrupts` — случайные `float64` полной точности | без сжатия 9,0 МБ, 16,5 мс; gzip 4,37 МБ, 81,6 мс; zstd 4,14 МБ, 45,5 мс |
| Страница: сведение 1408 серий в 16 линий после одной записи | 0,06 мс от первого изменённого времени против 6,8 мс за всё окно (Node, медиана 30 записей, 3 прогона) |

Полное окно страница получает один раз, когда открывает секцию; дальше каждый ответ несёт только новые точки. Размер полного окна задают значения: короткие числа сжимаются в 2,9 раза, `float64` полной точности — в 2,2.

## Что держит цену низкой

| Где | Как |
| --- | --- |
| Запрос `/api/series` | страница называет measurement с `seq` своего последнего ответа, а не каждую серию: размер запроса растёт с числом секций, а не серий. Сервер отдаёт только точки, записанные после этого `seq` ([Плагин hostdash](plugin.md#api)) |
| Ответ ленты | времена одного сбора общие у серий measurement и идут один раз на measurement; у серии только значения. Время — первое и шаги |
| Долгое отсутствие | у каждой точки номер записи, поэтому вкладка, скрытая сколько угодно, получает только пропущенные точки, а не окно целиком |
| Ожидание изменений | один ждущий запрос на запись (long polling, [Плагин hostdash](plugin.md#ожидание-изменений)); статусы в ответе; раскладка только при новой `version` или `start`; в фоновой вкладке запросов нет |
| Статусы | считаются один раз на запись и делятся между всеми ждущими запросами |
| Секции конфига | разбираются один раз в `Init` в карту по measurement |
| Группа метрики | ищется по `HashID` метрики, без карты тегов и ключа на каждую метрику |
| Ответы | плагин сжимает их сам (zstd, gzip), до прокси ([Плагин hostdash](plugin.md#сжатие)) |
| Файлы страницы | ETag по содержимому: повторная загрузка получает `304` |
| Страница: линии | график держит сведённые линии и пересчитывает только моменты от первого изменённого времени; если серии графика не менялись, только сдвигает ось |
| Страница: часы | раз в 1 с сдвигают ось времени, только если сдвиг не меньше пикселя; без сети |
| Страница: предел линий | не больше `chart_lines` линий на графике (по умолчанию 100), верхние по пику |
| Легенда | пик каждой линии считается один раз до сортировки: O(L·U), L — линии, U — точки |
| Подсказка при наведении | строит до `tip_lines` строк (по умолчанию 20) вокруг линии под курсором |
| `/api/status` | считает только статусы, раскладку не строит |
| Overview | точек не запрашивает, только статусы |

- Telegraf выравнивает время сбора по интервалу (`round_interval = true` по умолчанию), поэтому у групп одного сбора одно время, и `uPlot.join` строит таблицу L × U, без роста от разных времён.
- JS меряется в Node: в браузере время зависит от того, видна ли вкладка, и для сравнений не годится.
