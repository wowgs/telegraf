# Инпут schedstat: дизайн

Инпут `inputs.schedstat` собирает очередь к каждому ядру из `/proc/schedstat`. Главная дока ветки — [Дизайн](../../../outputs/hostdash/docs/design.md); конфиг и пример вывода — [README](../README.md).

Load average ядро считает одним числом на всю машину: сумма по ядрам задач, которые работают или ждут процессор (`nr_running`), и задач в непрерываемом сне (`nr_uninterruptible`), сглаженная экспонентой раз в 5 с (`kernel/sched/loadavg.c`, строки 18–27). По ядрам его не получить: `nr_uninterruptible` по ядру неточен, смысл имеет только сумма (там же, строки 49–53). Очередь к каждому ядру ядро отдаёт в `/proc/schedstat`.

- **Источник.** Строка `cpu<N>` в `/proc/schedstat`, поля 7–9 по `Documentation/scheduler/sched-stats.rst`: время работы задач на этом ядре (нс), время, которое задачи ждали очереди на этом ядре (нс), число квантов. Это накопительные счётчики. Поля 1–6 заполняются только при `kernel.sched_schedstats = 1` (по умолчанию 0), инпут их не берёт. Строки доменов (балансировка) не берёт тоже.
- **Версии.** Строка `cpu<N>` одинакова в версиях 15, 16 и 17: они меняли только строки доменов. На проверенных машинах (Raspberry Pi 5 с ядром 6.18, x86-сервер с ядром 7.0) версия 17. Другую версию инпут не читает: `Init` возвращает ошибку, потому что поля могли поменять смысл.
- **Разбор** — `Schedstat()` из `github.com/prometheus/procfs` v0.22.0, которую Telegraf уже использует. Строку `version` читает сам инпут.
- **Схема метрики** — одна метрика на ядро за сбор, тип counter:

    | | |
    | --- | --- |
    | measurement | `schedstat` |
    | тег `cpu` | `cpu0`, `cpu1`, … — как в `/proc/schedstat` и у `inputs.cpu` |
    | поле `run_time_ns` | uint64, время работы задач на ядре, нс |
    | поле `wait_time_ns` | uint64, время ожидания очереди на ядре, нс |
    | поле `timeslices` | uint64, число квантов на ядре |

    Строки по всей машине нет: сумму по ядрам считает тот, кто показывает метрики, например страница hostdash. Других тегов, кроме `host` от агента, нет.
- **Конфиг** — опций нет. Путь к `/proc` берётся из `HOST_PROC`, как у штатных инпутов на procfs.
- **Платформы.** Только Linux. На других `Init` пишет предупреждение, `Gather` ничего не делает, как у `kernel_vmstat`.
- **Что из этого видно.** Скорость `wait_time_ns` в секундах за секунду — среднее число задач, ждавших очереди к ядру за интервал: 1,0 — одна задача ждала всё время. Скорость `run_time_ns` — доля времени, когда ядро было занято. Сумма обеих — средняя длина очереди к ядру: аналог load по ядру без ожидания диска и без сглаживания. Это вывод из смысла полей (закон Литтла), на данных не проверен.
- **Тесты** — разбор файлов из `testdata/` (версия 17 с Raspberry Pi 5 и x86-сервера, версия 15, неизвестная версия, нет файла), метрики через `testutil.Accumulator`, `Init` на неподдерживаемой версии. Тесты только для Linux; на macOS их гоняют в Docker (alpine).
